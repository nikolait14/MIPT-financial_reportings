# Поддержка дополнительных статей КФЗ

## Основание

Организаторы подтвердили: при проверке могут встретиться статьи, которых нет в
выданном наборе на Google Drive. Следовательно, набор `0200`, `0300`, `0800`,
`0900` — это покрытие кейса 19, а не закрытый справочник продукта.

## Принцип

Код статьи и ее положение в отчете являются данными схемы КФЗ. Они не должны
быть зашиты в алгоритм сверки. Алгоритм обязан показать каждую статью,
распознанную в схеме отчета, независимо от того, есть ли для нее уже правила
классификации первичных документов.

## Контракт схемы

Старый компактный формат продолжает работать:

```json
"article_report_fields": {
  "0200": "wages_total",
  "0300": "insurance_total"
}
```

Расширяемый формат задает код непосредственно у колонки строки КФЗ:

```json
"report_row_fields": [
  {
    "field_id": "materials",
    "field_name": "Материальные затраты",
    "article_code": "0400",
    "article_name": "Материальные затраты"
  },
  "row_total"
]
```

Оба формата можно использовать вместе, если они не дают конфликтующих
отображений `код статьи → поле отчета`. При запуске схема валидируется:
дубликат `field_id` или ссылка на отсутствующее поле — контролируемая ошибка
конфигурации, а не тихо неверная сверка.

## Семантика неизвестной статьи

| Ситуация | Результат |
|---|---|
| Статья есть в КФЗ и для нее есть правила | Обычная классификация и сверка |
| Статья есть в КФЗ, но правил нет | `INSUFFICIENT_DATA / UNSUPPORTED_ARTICLE` |
| Поле статьи извлечь не удалось | Ошибка извлечения КФЗ; не подставлять ноль |
| В документе найдено назначение без классификации | Операция `REVIEW`, без автоматического отнесения к неизвестной статье |

`UNSUPPORTED_ARTICLE` сохраняет сумму из КФЗ, название, evidence и место в
формуле общего итога. Он означает «статья замечена, но пока не доказуема», а не
«статья равна нулю» и не «расхождения нет».

## Реализация

- Добавлен модуль `financial_verification.report_schema`: он получает список
  полей строки и карту статей из конфигурации, без перечня статей в коде.
- OCR-пайплайн, выделение областей КФЗ и reconciliation используют эту схему.
- Для статьи без правила создается явный результат с
  `article_supported: false`, `supported_value: null` и
  `UNSUPPORTED_ARTICLE`.
- Сумма всех распознанных статей, включая пока неподдерживаемые, участвует во
  внутренней проверке `row_total`.
- Добавлен регрессионный тест с `0400`, которого нет в наборе правил.

## Дальнейшее расширение

Для каждой новой статьи команда добавляет отдельное правило классификации и
набор примеров только после проверки предметным экспертом. Нельзя автоматически
переносить документы из `REVIEW` в новую статью на основании ее кода или
соседства в форме.
