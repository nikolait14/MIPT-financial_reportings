# План UI отчета и просмотра доказательств

## Статус

Реализован минимальный локальный web-клиент, доступный с `/`: загрузка
комплекта, SSE-прогресс, быстрый отчет, таблица статей и evidence viewer с
bbox-overlay. Он не требует отдельного frontend-сервера или внешних сервисов и
использует `HttpOnly` сессию backend. `EvidenceReference` теперь содержит
сессионный `page_url`, который frontend не конструирует сам.

Завершена первая UX-доработка viewer: у расхождения есть явная кнопка
`Посмотреть доказательства`; при открытии изображения система автоматически
приближает и прокручивает его к bbox, а пользователь может менять масштаб,
вернуть вид к выделению или прокрутить страницу. Для XLSX добавлен отдельный
сессионно-защищенный grid-viewer: листы, заголовки, использованный диапазон,
значения, формулы и подсветка ячеек из evidence. Диапазон ограничен 120
строками и 40 колонками, поэтому API не отдает клиенту весь объект книги.
Таблица намеренно компактна: в ней виден результат вычисления, а не текст
формулы. Формула открывается в расположенной над таблицей formula bar только
по двойному клику по ячейке, как в Excel. Сначала используется сохраненное
Excel значение, а для простого `SUM` без кэша — локальное вычисление по ячейкам
книги. Для простых ссылок и диапазонов formula bar перечисляет использованные
ячейки и подсвечивает их синим.

## Цель

Превратить технический результат сверки в понятный пользовательский отчет с
двумя режимами: быстрым обзором и детальной проверкой каждого расхождения по
исходным документам.

Этот этап строится поверх реализованного `Source Evidence API`. Финансовая
логика, классификация и сессионная авторизация не дублируются на frontend.

## Пользовательские сценарии

### Быстрый отчет

Пользователь после загрузки комплекта видит:

- итог: `REPORT_UNRELIABLE`, `INSUFFICIENT_DATA` или надежность проверенных
  показателей;
- значение КФЗ, подтвержденную сумму, дельту и количество источников;
- таблицу статей со статусом и понятным объяснением;
- отдельные блоки для `REVIEW`, `UNSUPPORTED_ARTICLE` и технических ошибок.

Технический reason code может быть доступен как дополнительная деталь, но не
является главным текстом для пользователя.

### Детальная проверка

Клик по статье или дельте открывает инспектор:

```text
Слева                              Справа
─────────────────────────────      ─────────────────────────────
Статья 0800                         Страница КФЗ / документа
КФЗ: 1 145 798,10 ₽                 с подсветкой bbox
Подтверждено: 1 133 298,10 ₽
Дельта: +12 500,00 ₽

Формула и четыре источника          Переключатель источников
OCR confidence и исходный текст     Увеличение и прокрутка
```

Пользователь может перейти от значения КФЗ к каждому первичному документу,
увидеть выделенный фрагмент, исходный текст и способ извлечения.

## План реализации

| Шаг | Результат | Критерий приемки |
|---|---|---|
| 1. API-polish | `EvidenceReference` содержит `page_url`, размер страницы, bbox, confidence и доступность preview | Frontend не собирает URL к файлу самостоятельно |
| 2. Каркас клиента | Загрузка файлов, создание проверки, SSE-прогресс и экран результата | Комплект отправляется без перезагрузки страницы |
| 3. Быстрый отчет | Итог, карточки сумм, таблица статей и человеческие статусы | Причина расхождения понятна без чтения JSON |
| 4. Evidence viewer | Рендер image preview, zoom, переключатель документов и bbox overlay | Клик по дельте открывает правильную страницу и фрагмент |
| 5. Состояния | `REVIEW`, `UNSUPPORTED_ARTICLE`, нет bbox, pipeline failure, `410` | Нет ложного статуса «корректно» или пустого экрана |
| 6. Приемка | Сквозной UI/API тест на кейсе 19 | Видны КФЗ, четыре источника и дельта 12 500,00 ₽ |

## Требования к API

Используются существующие сессионно-защищенные endpoints:

```text
POST /api/v1/verifications
GET  /api/v1/verifications/{id}/events
GET  /api/v1/verifications/{id}/result
GET  /api/v1/verifications/{id}/documents
GET  /api/v1/verifications/{id}/documents/{document_id}/pages/{page}
GET  /api/v1/verifications/{id}/documents/{document_id}/spreadsheet?sheet={sheet}
GET  /api/v1/verifications/{id}/evidence/{evidence_id}
```

В `EvidenceReference` должен присутствовать готовый относительный `page_url`.
Он не является публичной ссылкой: browser автоматически передает `HttpOnly`
cookie сессии, а backend снова проверяет `owner_session_hash`.

## Ключевые UI-правила

1. `MISMATCH` выделяется как подтвержденное финансовое расхождение.
2. `INSUFFICIENT_DATA`, `REVIEW` и `UNSUPPORTED_ARTICLE` не окрашиваются как
   финансовая ошибка и содержат объяснение границы проверки.
3. Если bbox отсутствует, viewer показывает страницу и исходный фрагмент без
   фиктивной подсветки.
4. Confidence — это характеристика извлечения, а не вероятность финансовой
   ошибки.
5. В UI не выводятся server path, SHA-256 как основной текст или постоянная
   ссылка на документ.
6. При `410` пользователь получает понятное сообщение о завершении временной
   сессии и возможность загрузить комплект заново.

## UX-доработка evidence viewer

Первый реализованный viewer технически умеет показать bbox, но вход в него
нельзя прятать в неочевидный клик по строке таблицы. Пользователь не обязан
догадываться о скрытой интерактивности.

### Явный вход в доказательства

Для каждого `MISMATCH` в быстрой таблице и в верхней карточке итога нужна
основная action-кнопка:

```text
+12 500,00 ₽   [Посмотреть доказательства]
```

Она сразу открывает детальный режим с evidence КФЗ, а не только выделяет
строку. В детальном режиме источники должны быть пронумерованы и названы по
роли: `1. КФЗ`, `2. Акт №…`, а не представлены неясным списком файлов. У
каждого источника есть действие `Показать фрагмент`.

При первом открытии следует показать ненавязчивую подсказку: «Выберите
источник слева — система подсветит значение справа».

### PDF/PNG viewer

В первой версии панель viewer включает:

```text
[−] [Вместить] [+] [К выделению]
```

- `К выделению` — действие по умолчанию при выборе evidence: страница
  автоматически масштабируется и прокручивается к bbox;
- при увеличении доступна прокрутка изображения внутри панели;
- подпись под preview объясняет, что рамка отмечает фрагмент извлечения, а не
  меняет оригинальный PDF.

`Ctrl/Cmd + колесо`, drag-to-pan, полноэкранный режим и ручной переключатель
страниц остаются следующей UX-итерацией. Переключение evidence уже открывает
нужную страницу автоматически.

Если bbox отсутствует, кнопка `К выделению` недоступна, а пользователь видит
исходный текст evidence и ясное объяснение причины.

### XLSX viewer

XLSX не следует представлять как неинтерактивную картинку. Для него нужен
безопасный grid-viewer на основе извлеченных данных:

- переключатель листов;
- отображение используемого диапазона с заголовками строк и колонок;
- подсветка ячейки или диапазона из `EvidenceReference`;
- отображение значения в grid и формулы только по двойному клику в formula bar;
- подсветка ячеек, на которые ссылается простая формула текущего листа;
- отсутствие прямой передачи исходного пути или постоянной ссылки на файл.

Поиск по листу и действие `Показать в контексте` — следующая итерация. На
текущем шаге evidence сразу подсвечивает целевую ячейку без ручного поиска.

Такой viewer точнее связывает evidence `sheet/cell` с первичным расчетом, чем
рендер XLSX в PNG. Для DOCX следующим этапом применяется аналогичный подход:
структурированный текст с переходом к абзацу или строке таблицы.

### Приемка UX-доработки

- пользователь открывает доказательства `0800` одной видимой кнопкой;
- при открытии сразу видна подсвеченная ячейка КФЗ, без ручного поиска по
полной странице;
- можно приблизить, переместить и вернуть страницу к выделению;
- evidence XLSX открывает лист и подсвечивает связанную ячейку;
- отсутствие bbox, листа или preview не приводит к пустому экрану.

## Приемка на кейсе 19

- быстрый отчет показывает `REPORT_UNRELIABLE` и дельту `+12 500,00 ₽`;
- статья `0800` открывает evidence КФЗ и четыре подтверждающих источника;
- `0400` показана как неподдерживаемая статья, а не как финансовая ошибка;
- bbox КФЗ подсвечивает извлеченную ячейку;
- другая браузерская сессия получает `404` для отчета, evidence и page preview;
- после истечения TTL интерфейс корректно обрабатывает `410`.

## Вне этапа

- постоянная история проектов и версий документов;
- совместная работа и комментарии аудиторов;
- редактирование исходного PDF/DOCX/XLSX;
- публичные ссылки на evidence;
- мобильное приложение.
