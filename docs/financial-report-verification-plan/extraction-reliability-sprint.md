# Спринт надежного извлечения реквизитов

## Цель

Убрать опасное поведение, при котором реестр выбирает первое похожее значение
или наибольшую сумму, а затем формирует финансовый вывод с ложной точностью.
Неоднозначный документ не исключается и не влияет на итог «как ноль»: он
становится `REVIEW` с машиночитаемой причиной и исходным доказательством.

## План и границы

| Шаг | Решение | Критерий готовности |
|---|---|---|
| 1. Единый разбор денег | Вынести строгий parser числового литерала, запретить удаление OCR-букв и не считать дату суммой | `1O0,00` отвергается; `245 000 руб.` извлекается как `245000.00` |
| 2. Семантика суммы | Не выбирать «максимальное» число. Несколько сумм при НДС, другая валюта или масштабы `тыс./млн руб.` дают `REVIEW` | Нет неявной конвертации/выбора между НДС и итогом |
| 3. Период | Приоритет у явно подписанного периода и диапазона; несколько неподписанных дат дают `AMBIGUOUS_DATE_OR_PERIOD` | Дата подписания не подменяет период услуги; частичное попадание в окно не включается молча |
| 4. Сверка с REVIEW | Известная, но неклассифицированная сумма образует интервал возможной поддержки, а не скрывает все выявленные расхождения | Расхождение за границей интервала остаётся `MISMATCH`; неизвестная сумма оставляет `INSUFFICIENT_DATA` |
| 5. Регрессия | Добавить unit-тесты и прогнать набор кейса 19 в Docker | Существующий результат кейса 19: дельта `12 500,00` сохраняется |

## Правила принятия решения

```text
строгий разбор не удался / валюта или единицы не поддержаны
    -> REVIEW, причина извлечения

несколько сумм с НДС
    -> REVIEW / AMBIGUOUS_VAT_AMOUNT

несколько дат без понятной подписи
    -> REVIEW / AMBIGUOUS_DATE_OR_PERIOD

известная REVIEW-сумма R и подтверждённая сумма S
    -> допустимый диапазон статьи: [S, S + R]
    -> значение КФЗ вне диапазона: подтверждённое MISMATCH
    -> значение внутри диапазона: INSUFFICIENT_DATA

REVIEW-документ без надёжной суммы
    -> INSUFFICIENT_DATA: верхняя граница не известна
```

Сумма `R` не распределяется между статьями автоматически: для каждой статьи
используется консервативная верхняя граница `S + R`. Это не доказывает, что
неопознанный документ относится к этой статье; это только не позволяет ему
скрыть расхождение, которое остаётся даже при самом благоприятном распределении.

## Вне этого спринта

- полноценный нативный PDF text-layer и многостраничный OCR;
- OCR confidence / повторное распознавание ячейки КФЗ;
- валютные курсы, кредит-ноты и автоматическая трактовка НДС;
- UI для ручного выбора суммы и периода.

Эти возможности требуют отдельного продуктового правила, а не эвристики
извлечения. Текущая реализация сохраняет доказательство строки и reason code,
чтобы UI мог запросить решение пользователя.
