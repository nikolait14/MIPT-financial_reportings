# Hardening и демонстрационная приемка

## Финансовая нормализация

- Денежные значения разбираются как `Decimal` и округляются до копейки по
  `ROUND_HALF_UP`.
- Отрицательные суммы поддерживаются для корректировок и сторно, если знак
  является частью денежного литерала, а не дефиса в идентификаторе.
- Значения в `тыс. руб.` и `миллионах рублей` нормализуются в рубли до
  агрегирования.
- Документы с USD/EUR не смешиваются с RUB: они переходят в `REVIEW` с
  `UNSUPPORTED_CURRENCY`, пока для контекста не задано правило конвертации.
- Неоднозначная единица измерения также переводит документ в `REVIEW`.

## Evidence по форматам

| Формат | Просмотр в UI |
|---|---|
| PDF/PNG | Страница, bbox, масштаб и автофокус. |
| XLSX | Ячейка/диапазон, значение; формула и зависимости по двойному клику. |
| DOCX/TXT | Структурированный текст с подсветкой evidence-абзаца или строки таблицы. |

Все preview выдаются только защищенному владельцу сессии и не раскрывают путь
на сервере. В EPHEMERAL-режиме они исчезают вместе с workspace по TTL.

## Сценарии регрессии

| Сценарий | Ожидаемое поведение |
|---|---|
| Новая статья КФЗ | Видна как `UNSUPPORTED_ARTICLE`, не превращается в ноль. |
| Пересохраненный дубль | `POSSIBLE_DUPLICATE_DOCUMENT / REVIEW`, не суммируется автоматически. |
| Частичный выход за период | `PARTIALLY_OUT_OF_PERIOD / REVIEW`. |
| Отрицательная корректировка | Сумма со знаком агрегируется через `Decimal`. |
| Тысячи рублей | Нормализуются до RUB до сверки. |
| Валюта, отличная от RUB | Явный `UNSUPPORTED_CURRENCY`, без ложного сложения. |
| Поврежденный файл | Обрабатываются остальные документы; итог получает границу проверяемости. |
| XLSX без Excel-кэша формулы | Ограниченный `SUM` вычисляется локально; формула остается проверяемой. |

## Демонстрация

1. Загрузить кейс 19, показать `0800` и доказательства дельты 12 500 руб.
2. Открыть PDF/PNG evidence, XLSX-ячейку и DOCX/TXT evidence.
3. Показать статус вероятного дубля и объяснить, почему это `REVIEW`, а не
   автоматическое исключение.
4. Показать `INSUFFICIENT_DATA` на неполном комплекте как честный отказ от
   финансового вывода.

## Закрытые сценарии и пользовательский контроль

- `docker compose up -d --build api && docker compose run --rm smoke-api` —
  сквозная проверка кейса 19 через публичное API: сессионная изоляция,
  загрузка, итог, JSON/Markdown-экспорт и координатное доказательство.
- Файл с совпадающими реквизитами, но другим SHA-256, остаётся в `REVIEW`.
  Эксперт выбирает «Исключить копию» или «Учитывать отдельно»; решение
  создаёт новый запуск в той же сессии и не меняет исходный результат.
- Для неожиданной статьи эксперт может перед запуском задать код, название и
  текстовые признаки. Правила объединяются с базовыми лишь в workspace
  запуска и удаляются вместе с ним в EPHEMERAL-режиме.
- Экран качества показывает охват комплекта, долю ручной проверки,
  технические ошибки и число финансовых выводов. Это операционные метрики,
  а не метрики точности модели: последние требуют размеченного эталона.
